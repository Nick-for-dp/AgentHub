## Why

营销部试用 AgentHub 对话前端后，反馈当前界面存在面向用户的文案和信息暴露问题：

- 未登录提示带有“官网”语境，不适合所有嵌入场景。
- 空会话提示直接暴露 Agent code `qa`，对普通客户缺少意义。
- 工作流节点明细默认展开，视觉噪音大，也会让用户误以为需要关注每个内部步骤。
- 工作流运行中的“工作流正在执行”偏技术化，与用户实际感知的“搜索答案”不一致。
- 多种错误路径向前端展示不同细节，用户难以理解且可能暴露内部状态。

本提案对应 `PLAN.md` 之外的新增需求：对现有对话页做一次小范围、可独立回滚的用户文案与信息层级修正。目标是让对话页更像面向客户的问答入口，而不是运行时工作台。

## What Changes

- 未登录状态下，嵌入式对话页提示统一为“请先登录”；普通 `/chat` 页面继续提供“请先登录”登录入口。
- 空会话欢迎语由“向「{agentCode}」Agent 提问”改为“请提问”。
- 助手消息的工作流节点明细默认折叠；工作流摘要保留，用户仍可手动展开查看步骤。
- 工作流运行中的标题由“工作流正在执行”改为“正在搜索”；完成、失败文案不变。
- 聊天页所有用户可见错误提示统一为“抱歉，出错了”，不向用户展示具体 HTTP、权限、运行时或 provider 错误文本。
- 同步 `docs/frontend-design.md` 与 `docs/embed-token-sequence.mmd` 中的界面事实。

## Capabilities

### New Capabilities

- `chat-experience`：约束面向客户的聊天页状态文案、工作流过程默认信息层级，以及统一错误提示。

### Modified Capabilities

无。

## Impact

- **受影响页面**：`frontend/src/pages/chat/ChatPage.vue`。
- **受影响行为**：聊天页未登录提示、空会话欢迎语、工作流步骤默认展开状态、运行中文案、错误提示显示文本。
- **保持不变**：SSE 事件契约、Dify runtime 调用、后端 API、权限判断、401 重新授权/跳转、embed token exchange、调用记录、产品会话和审计日志。
- **测试**：新增 `ChatPage` 聚焦回归测试；`npm test` 与 `npm run build` 必须全绿。
- **文档**：更新前端设计规范和 embed token 时序图文案；归档时更新 `CHANGELOG.md`。
