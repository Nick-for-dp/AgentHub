## ADDED Requirements

### Requirement: 对话页使用客户向状态文案

聊天页 MUST 使用面向外部客户的简洁文案，不向用户暴露 Agent code 或不适用于所有嵌入场景的“官网”语境。

#### Scenario: 未登录 embed 对话页

- **WHEN** 用户以 embed 模式打开聊天页且尚未建立 embed session
- **THEN** 页面显示“请先登录”
- **AND** 不显示“请先登录官网”

#### Scenario: 未登录普通对话页

- **WHEN** 用户打开普通 `/chat` 页面且未登录
- **THEN** 页面显示“请先登录”登录入口

#### Scenario: 空会话欢迎

- **WHEN** 用户可聊天且当前会话没有消息、也未被 loading 状态占用
- **THEN** 欢迎语显示“请提问”
- **AND** 不向用户显示 `agentCode`、`qa` 或“Agent”技术标识

### Requirement: 工作流过程默认折叠且运行文案面向客户

聊天页 MUST 默认隐藏助手消息的工作流节点明细，但 MUST 保留工作流摘要供用户了解运行状态并手动展开明细。

#### Scenario: 新问题开始工作流

- **WHEN** 用户发送问题并开始接收节点事件
- **THEN** 工作流摘要可见，节点明细默认不展开
- **AND** 运行中摘要标题显示“正在搜索”

#### Scenario: 恢复历史助手消息

- **WHEN** 用户恢复、切换或重新加载包含工作流步骤的助手消息
- **THEN** 节点明细默认不展开
- **AND** 用户点击工作流摘要后可展开并查看步骤

#### Scenario: 工作流结束状态

- **WHEN** 工作流完成或失败
- **THEN** 完成摘要标题保持“工作流已完成”
- **AND** 失败摘要标题保持“工作流执行失败”

### Requirement: 聊天页错误提示统一

聊天页遇到请求、流式、鉴权、会话或语音错误时，所有用户可见错误提示 MUST 使用统一文案“抱歉，出错了”。具体 HTTP 状态、权限原因、运行时原因、provider 原文和内部异常信息 MUST NOT 通过聊天页错误提示暴露给用户。

#### Scenario: 流式调用失败

- **WHEN** 聊天请求返回 4xx、5xx、网络错误或 SSE `error` 事件
- **THEN** 聊天页用户可见错误提示为“抱歉，出错了”
- **AND** 不展示具体状态码、后端 message、Dify/provider 原文或内部异常

#### Scenario: 鉴权过期

- **WHEN** 普通登录态或 embed session 在聊天过程中过期
- **THEN** 用户可见错误提示为“抱歉，出错了”
- **AND** 普通登录态仍执行登录态清理与重定向
- **AND** embed 模式仍执行 token 重取

#### Scenario: 会话操作失败

- **WHEN** 恢复、切换或删除会话失败
- **THEN** 用户可见错误提示为“抱歉，出错了”

#### Scenario: 语音输入失败

- **WHEN** 浏览器麦克风权限、录音或转写失败
- **THEN** 用户可见错误提示为“抱歉，出错了”

#### Scenario: 排障信息保留在后端

- **WHEN** 任意聊天页错误发生
- **THEN** 后端错误码、日志、SSE 事件和 `agent_invocation_record` 继续按既有契约记录真实原因
- **AND** 本需求只改变前端用户可见文案，不吞掉服务端审计信息

### Requirement: 错误显示统一不改变恢复行为

统一错误提示 MUST 只影响展示文本，不得删除或绕过既有鉴权、权限、会话和请求状态收敛逻辑。

#### Scenario: 401 恢复控制流保持

- **WHEN** 聊天请求返回 401
- **THEN** 普通模式仍清理失效登录态并跳转登录页
- **AND** embed 模式仍请求新 token，页面提示仅替换为“抱歉，出错了”

#### Scenario: 403 与 503 控制流保持

- **WHEN** 聊天请求返回 403 或 503
- **THEN** 请求结束、loading 状态收敛和会话列表刷新逻辑保持原行为
- **AND** 用户只看到“抱歉，出错了”
