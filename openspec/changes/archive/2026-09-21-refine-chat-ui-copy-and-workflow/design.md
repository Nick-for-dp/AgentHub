## Context

对话页集中在 `frontend/src/pages/chat/ChatPage.vue`：

- 未登录分支由 `canChat` 控制；embed 模式当前显示“请先登录官网”，普通模式已显示带跳转按钮的“请先登录”。
- 空会话欢迎语直接插值 `agentCode`，当前默认值为 `qa`。
- 工作流摘要和节点明细由 `expandedSteps` 控制；节点明细可展开，但生命周期中的多个状态重置点需要统一保证默认折叠。
- 运行状态文案由 `getWorkflowTitle` 产出，摘要卡片继续承担运行感知。
- 错误提示统一写入 `errorMsg`，但不同分支当前写入不同的 HTTP、权限、运行时、会话或语音错误文本。

相关规范为 `docs/frontend-design.md` 的“用户对话界面规范”和 `docs/ui-review-checklist.md`。本次不调整页面布局、视觉体系、消息气泡和输入区。

## Goals / Non-Goals

**Goals:**

- 用面向客户的短文案替换技术化或平台内部语境。
- 保留工作流摘要作为运行反馈，但默认隐藏节点明细。
- 统一聊天页用户可见错误提示，同时保持认证恢复和审计行为不变。
- 用聚焦前端测试锁住上述行为。

**Non-Goals:**

- 不改后端错误码、错误日志、调用记录、SSE `error` 事件结构和 Dify 调用链。
- 不改登录页、管理端页面、普通 `/chat` 之外的页面错误提示。
- 不改工作流摘要卡片的布局、颜色、完成/失败状态和节点数据结构。
- 不删除或停止采集 `node_trace`，不改变节点事件处理逻辑。
- 不引入新依赖。

## Decisions

### D1. 聊天页使用客户向固定文案

embed 模式未登录提示改为“请先登录”；普通模式继续显示“请先登录”按钮。空会话欢迎语固定为“请提问”，不再向用户展示 `agentCode`。`agentCode` 仍用于 API 路由和会话请求。

### D2. 节点明细默认折叠，摘要保持可见

新建流式助手消息、恢复历史消息、切换会话和新建会话时，均不得默认设置该消息的 `expandedSteps` 为 `true`。工作流摘要继续显示状态、步数、最近节点和箭头；用户点击摘要后仍可展开节点明细。

实现优先保持现有 `expandedSteps: Record<string, boolean>` 结构，以“缺省即折叠”为唯一默认约定，避免为单次展开引入额外状态机。

### D3. 运行中文案只改标题

`getWorkflowTitle` 的 running 分支返回“正在搜索”；`finished` 仍为“工作流已完成”，`failed` 仍为“工作流执行失败”。详情、步数、节点状态不改。

### D4. 聊天页错误展示统一，不吞掉恢复行为

在 `ChatPage.vue` 内集中定义用户可见错误文案常量，例如 `USER_ERROR_MESSAGE = '抱歉，出错了'`，所有写入 `errorMsg` 的用户可见错误分支统一使用该文案，包括：

- 发送消息时的 401、403、503 及其他流式/网络错误；
- embed 鉴权交换失败和鉴权过期；
- 会话恢复、切换、删除失败；
- 语音输入失败。

分支原有的状态收敛和恢复动作必须保留：401 清理登录态或请求 embed token、503 不改变后端行为、语音错误不再向用户展示浏览器原文。后端仍返回并记录真实错误码、消息和调用记录；本决策只约束前端展示。

### D5. 用聚焦组件测试替代纯文案 grep

新增 `ChatPage` 测试基线，覆盖：

- embed 未登录和普通未登录都显示“请先登录”；
- 空会话显示“请提问”，不显示 `qa`；
- 工作流节点明细默认不渲染，点击摘要后可渲染；
- 运行中摘要标题为“正在搜索”；
- 代表性错误分支显示“抱歉，出错了”，认证恢复动作仍被调用。

测试可用现有 Vitest + Vue Test Utils 和组件依赖 mock 实现，不引入浏览器 E2E 依赖。

## Risks / Trade-offs

- [统一错误文案会降低前端排障信息量] -> 保留后端日志、错误码、SSE 事件与调用记录；如需定位问题，以 request_id 和后端审计为准。
- [默认折叠状态在恢复/切换路径漏掉] -> 测试覆盖流式新消息与历史消息恢复两个主路径；代码 review 检查所有 `expandedSteps` 写入点。
- [改文案影响 embed 文档事实] -> 同步修改 `docs/embed-token-sequence.mmd` 和 `docs/frontend-design.md`。
- [ChatPage 依赖较多导致测试脆弱] -> 只 mock 测试所需 API、router、store 和子组件，断言用户可见行为，不断言内部实现细节。
